# Labs 05–06 Design

## Goal

Create two isolated, reproducible course laboratories: a WDK Lightning wallet app and a Taproot-versus-EVM transaction forensics report.

## Lab 05 architecture

`lab05-lightning/` is a Node.js app whose HTTP API owns one long-lived WDK Lightning wallet instance. The wallet is initialized once per process from `WDK_MNEMONIC`, while encrypted application state is persisted in a local data directory and never recreated per request. The API exposes invoice creation, invoice status, and payment; the browser UI consumes only public invoice/payment data.

The persistence adapter will use authenticated encryption with a key supplied through `WDK_STORAGE_KEY`; the mnemonic remains environment-only and is never serialized, logged, rendered, or committed. The app will include a mockable wallet boundary so unit and integration tests never require real funds, while production configuration can connect to the WDK Lightning implementation.

## Lab 06 architecture

`lab06-forensics/` contains a small data-fetch/decode utility plus `TX_FORENSICS.md`. Network lookups are explicit and reproducible, and the report stores raw public transaction metadata, calldata, witness elements, and ABI/function inventory before interpretation. No wallet credentials are needed.

## Deliverables

- `lab05-lightning/DEPLOY.md` with placeholder fields for Vercel URL, public node ID, and cross-payment evidence.
- `lab06-forensics/TX_FORENSICS.md` with one ETH HTLC-pattern transaction, one BTC Taproot HTLC-pattern transaction, one verification transaction per chain, raw data, and an explicit definition of “better”.
- Root documentation explaining setup, tests, secret handling, and the boundary between local preparation and user-authorized deployment/payment.

## Security constraints

- Never create, print, store, commit, or request a real mnemonic/private key in the repository.
- Commit only `.env.example` placeholders and redact sensitive invoice/payment evidence unless the user explicitly supplies public evidence for documentation.
- Validate all request inputs and avoid leaking wallet errors or environment values in HTTP responses.
- Vercel deployment and Lightning payments remain user-authorized external actions.
